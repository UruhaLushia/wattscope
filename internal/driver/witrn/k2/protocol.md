# K2 普通上报

以 64 字节 `FF 55` 帧起点为偏移 0。固件 V6.0 的 `0x1A` 上报函数在 `0x08013928` 构造载荷，封装函数在 `0x08065154` 写入帧头。偏移 2～7 分别是设备毫秒计数 `tick` 的 `tick / 1000`、`tick % 1000`、`tick / 30`、`tick / 100`、`tick % 100`、`tick / 80`，每项按整数运算并取低 8 位。结合偏移 26 的开机秒数可以还原毫秒计数。六份抓包中的 29,217 条普通帧全部符合此布局。

V6.0 固件将偏移 10～11 写为零，测量字段写到偏移 56，随后复制并发送完整 52 字节载荷。偏移 57～61 对应未初始化的栈字节。关闭 PD 联机的抓包中，14,127 条普通帧均以 `08 A5 06 00 20` 填充这五个位置。开启时，观察到的 13 次尾部后四字节清零都紧跟 `FE` 帧。`0x1A` 载荷没有快充协议名或能力列表字段。

Linux 的「检查联机」通过单独的 HID 句柄发送 `0x19`，按 V6.0 固件配置读取路径查询 EEPROM 偏移 `0x61` 的位 6。页面显示最近一次成功读回的保存值，断线后重新检查。没有收到 `FE` 帧时不能仅凭普通遥测判断开关状态。
